# 解释性 HTML 交付

适用规则：[文档治理 RULE-026](../logic_domains/document-governance/logic_readme.md)。需要持久、可视化的流程、架构、方案比较或项目状态说明时读取；简单问答无需生成页面。

## 输出步骤

1. 使用当前项目根的 `explainers/`，没有则按需创建；不要固定到 EduAI 的绝对路径。先看已有相关页面，沿用项目的视觉与命名约定。
2. 持续维护的说明优先更新 `explainers/<topic>.html`；需要保留日期快照时用 `<topic>-YYYYMMDD.html`，页内明确快照日期。同一主题避免无意义的 v2/final 副本。
3. 先从当前 readme/change 和必要代码、验证证据整理结论，再生成 HTML。页面给出标题、结论、适当的流程图/对照、证据来源链接、快照时间与尚未核实边界；结构按解释目标选择，不强制固定模板。
4. 项目状态页从同一声明范围的活跃索引重算计数，说明统计口径；区分开发交付、实际部署、验证边界，不能把 verifying 条数等同于缺陷数，也不能复制旧数字冒充当前状态。
5. 默认生成可直接本地打开的单文件 HTML，内联 CSS；必要交互用少量原生 JS，不依赖 CDN、构建服务或联网。页面在脚本不可用时仍展示核心内容，注意窄屏、键盘与打印可读性。
6. 打开浏览器检查实际页面、交互和来源链接，并核对桌面与窄屏布局；工具不可用时如实说明未完成的视觉核验，不把源码检查报成浏览器通过。
7. 在项目范围/产物登记中将 `explainers/` 标为可重建的展示交付物；只有展示产物的目录通常用 inherited，不为 HTML 新建一套领域制度。medium/high 的工作台账登记 keep，最终回复提供 HTML 的绝对路径可点击链接；支持时直接打开预览。

## 来源与维护

页面标明“解释快照，非现行制度”，用相对链接指向实际 readme、change、VER 或代码证据。规则变动先更新所属 readme/议案，再刷新相关 HTML；旧日期快照保留原日期。不要把尚未确认的方案写成现行事实，也不要只在 HTML 保存新决定。

参考形式是 EduAI 的 `explainers/`：独立主题页面、中文叙述、流程与对照、来源可追溯。复用呈现方式，不复制它的项目数据、环境路径或过期状态。
